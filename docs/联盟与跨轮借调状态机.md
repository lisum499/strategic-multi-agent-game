# 联盟与跨轮借调状态机

## 1. 文档定位

本文定义当前联盟军事力量跨轮借调规则和统一结算顺序，重点说明密封同时决策下的请求、履约、盟约失效、力量转移和事件公开问题。

## 2. 基本原则

1. 借调必须基于当前有效的双边盟约及其中明确的军事承诺。
2. 请求方不能在提出请求的同一轮立即使用所请求的力量。
3. 出借方必须在下一轮独立决定接受或拒绝；请求方看不到该轮的回应。
4. 接受请求不等于必然履约，还要检查盟约是否仍有效以及出借方是否有足够力量。
5. 借调力量必须先完成实际转移，依赖该力量的行动才可能生效。
6. 联盟状态变更在相应处理步骤立即生效；公开或私有事件在回合末统一投影和发布。

核心校验链为：

```text
盟约有效性 -> 出借方履约意愿 -> 出借方实际能力 -> 力量转移 -> 依赖行动校验
```

## 3. 跨轮流程

### 3.1 第 r 轮：提出请求

国家 B 根据有效的 A-B 盟约向 A 提交借调请求。主持人校验：

- A、B 均存活；
- A-B 盟约有效；
- 请求的力量类型属于盟约允许范围；
- 数量格式合法；
- 请求数量与尚未归还的同类借调力量之和不超过盟约承诺上限。

校验通过后生成 `pending_loan_request`。该请求只对 A、B 和主持人可见。本轮不发生力量转移，B 也不能在第 r 轮使用这部分力量。

### 3.2 第 r+1 轮：回应与条件行动

A 在密封决策中对请求选择接受或拒绝：

- 接受：进入盟约有效性和实际履约能力检查；
- 拒绝：借调失败，A-B 盟约立即破裂；
- 未回应：按拒绝处理，借调失败，A-B 盟约立即破裂。

B 可以提交依赖该请求的条件行动，但必须通过 `requires_loan_request_ids` 显式列出依赖的请求。B 看不到 A 在本轮的回应，因此不能据此临时修改行动。

## 4. 建议数据结构

### 4.1 待处理请求

`pending_loan_requests` 至少记录：

- `request_id`
- `alliance_id`
- `lender_id`
- `borrower_id`
- `force_type`：`conventional` 或 `nuclear`
- `amount`
- `created_round`
- `response_due_round`
- `status`

### 4.2 出借方回应

`loan_responses` 至少记录：

- `request_id`
- `lender_id`
- `decision`：`accept` 或 `reject`
- `round`

对不存在、已经结算、已过期或不属于该出借方的请求所作回应无效。

### 4.3 依赖借调的行动

每个行动可选填写 `requires_loan_request_ids`。其中任一请求未成功转移时，该行动整体取消。非依赖行动不受该请求失败影响。

## 5. 同轮统一处理顺序

所有国家提交密封决策后，主持人按以下顺序结算。排序必须固定，避免并发和字典遍历顺序影响结果。

### 5.1 冻结决策与存活检查

1. 冻结所有国家本轮提交的行动、借调回应、归还和联盟操作。
2. 检查行动方、出借方、借入方是否存活。涉及死亡国家的请求和回应直接失效。

### 5.2 处理回合开始时已经无效的盟约

盟约在回合开始时已经终止、过期或失效的，其待处理请求全部失败，依赖这些请求的行动取消。

### 5.3 处理主动毁约

任一方本轮主动解除盟约时，盟约立即失效：

- 该盟约下所有待处理借调请求失败；
- 依赖这些请求的行动取消；
- 不再读取或执行相关接受回应。

### 5.4 处理盟友之间的正增量行动

如果一方本轮准备对盟友实施正增量行动，盟约立即破裂。正增量行动包括外交、经济或军事施压，不仅指战争。

破裂后，该盟约下的待处理借调请求失败，依赖行动取消。

### 5.5 处理公开联盟造成的不兼容

联盟仅在相关军事借调达到公开门槛后成为“公开联盟”。当一个新公开联盟与现有关系冲突时，受影响的盟约立即失效。

例如 A-C 联盟本轮成为公开联盟，出现以下任一情况时，A-B 盟约失效：

- B 与 C 已有非零冲突值；
- B 本轮准备对 C 实施正增量行动；
- C 本轮准备对 B 实施正增量行动。

因此，A-B 盟约下尚未完成的借调请求失败，依赖行动取消。只有公开联盟参与此项第三方兼容性检查；秘密联盟不能被其他国家据此推断或约束。

### 5.6 读取出借方回应

对仍然有效的请求读取 A 的密封回应：

- 接受：继续进行资源检查；
- 拒绝或未回应：请求失败，A-B 盟约立即破裂，依赖行动取消。

拒绝原因、请求数值和盟约承诺属于双方私有信息。

### 5.7 预留出借方自身行动力量

先为 A 已提交的有效行动预留常规力量和核力量。借出力量不能与 A 自己的行动重复使用。

### 5.8 处理力量归还

处理本轮合法的借调力量归还。建议允许已经实际归还的力量在同一轮重新进入 A 的可借余额，但必须在所有实现中保持一致。

### 5.9 再次检查盟约承诺上限

计算：

```text
本次请求数量 + 当前尚未归还的同类借调数量 <= 盟约承诺上限
```

超过上限属于 B 的无效请求：该请求失败，但不因这一原因自动导致盟约破裂。

### 5.10 检查出借方实际能力

出借方可用力量为：

```text
可用力量 = 当前力量 - 自身行动预留 - 本轮此前已成功借出的力量
```

如果 A 已接受请求，但实际可用力量不足：

- 认定 A 无力履约；
- 该请求失败；
- A-B 盟约立即破裂；
- B 对该请求的依赖行动取消；
- 审计记录写明无力履约及计算依据。

当 A 同时接受多个请求时，按稳定的国家 ID 和请求 ID 顺序处理。余额不足导致的失败只破坏相应的出借关系，不连带破坏已经成功履行或尚有能力履行的其他盟约。

### 5.11 完成力量转移

通过全部检查后：

- 从 A 的可用力量中扣除借出数量；
- 将力量计入 B 的可用借调力量；
- 建立或更新借调台账；
- 将请求标记为已履约。

同一盟友提供给 B 的某类未归还军事力量累计达到 `1` 时，A-B 联盟强制公开。多次低于 `1` 的借调应累计计算。联盟一旦公开，后续即使力量归还，也不恢复为秘密状态。

### 5.12 复核依赖行动

力量转移完成后，再校验 B 的依赖行动：

- 所有依赖请求是否已经成功履约；
- 总资源是否充足；
- 是否满足常规或核行动门槛；
- 是否具备向目标区域投送核力量的能力；
- 实际核投入是否大于零；
- 同一份本国或借调力量是否被重复投入。

校验失败时只取消对应行动。除非规则另有明确规定，已经完成转移的借调力量不会因为行动取消而自动归还。

### 5.13 战斗与状态结算

完成借调和行动复核后，才进入常规冲突、核行动、存在指数转移、战损和胜负结算。

## 6. 盟约破裂和借调失败情形汇总

以下情况会使相关盟约立即破裂：

- 一方主动解除盟约；
- 盟友之间出现正增量行动；
- 新公开联盟使原盟约与第三方冲突关系不兼容；
- 出借方拒绝借调请求；
- 出借方到期未回应请求；
- 出借方接受后因实际力量不足而无法履约。

以下情况只使请求失败，默认不破坏盟约：

- 请求数量超过盟约承诺上限；
- 请求格式、力量类型或请求主体不符合盟约；
- 回应引用了不存在、过期或无权处理的请求。

如果盟约先因任何原因失效，则基于该盟约的所有未完成力量添加请求必然失败，且其依赖行动取消。

## 7. 事件生成与可见性

“回合末生成联盟事件”不应理解为回合末才改变联盟状态。正确做法是：

1. 在上述处理步骤中立即修改盟约、请求、台账和力量状态；
2. 同时向内部事件流追加完整事件；
3. 后续结算步骤读取已经更新的状态；
4. 回合结束时再按照可见性汇总并发布事件。

事件分为四层：

- **状态事件**：立即生效，供同轮后续规则读取。
- **公开事件**：回合末投影到公开记录。公开联盟破裂必须发布公开终止事件。
- **私有通知**：秘密联盟的建立、拒绝、无力履约和破裂只通知相关双方，并进入其下一轮观察。
- **完整审计**：保存请求、回应、处理顺序、计算过程、失败原因和最终结果，供主持人复核。

事件发布不得提前泄露密封决策。尤其不能在所有国家完成本轮提交前，向请求方透露出借方的接受或拒绝选择。

## 8. 实现验收条件

实现完成后至少应覆盖以下测试：

- 请求在提出当轮不能使用；
- 接受且力量充足时下一轮成功转移；
- 拒绝和未回应均导致盟约破裂；
- 接受但无力履约导致盟约破裂；
- 主动毁约优先于借调回应；
- 盟友间正增量行动使借调失败；
- 新公开联盟与第三方冲突使不兼容盟约失效；
- 超过承诺上限只拒绝请求，不自动毁约；
- 多请求按固定顺序处理且不超借；
- 达到累计公开门槛后联盟永久公开；
- 借调失败只取消显式依赖的行动；
- 公开记录、双方私有记录和完整审计的可见内容彼此正确隔离。
