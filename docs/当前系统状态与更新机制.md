# 当前系统 Agent、世界状态与更新机制

本文描述当前仓库 v6.0 已实现的状态、可见性、初始化方式和更新机制。规则实现主要位于：

- `src/strategic_game/protocol.py`：场景与决策校验、Agent 提示词。
- `src/strategic_game/runtime.py`：Agent 视图、密封决策、回合推进和回放。
- `src/strategic_game/rules.py`：冲突、存在转移、战损、胜负结算。
- `src/strategic_game/alliances.py`：联盟、借调、返还和相关事件。
- `src/strategic_game/capabilities.py`：核行动权限和二次打击。

## 1. 状态可见性

系统不把主持人的完整状态直接交给国家 Agent。每轮开始时，每个在场国家收到一份独立、不可变的轮初快照，并附带 `snapshot_hash`。

| 层级 | 所有国家可见 | 仅本国可见 | 仅主持人/审计记录可见 |
| --- | --- | --- | --- |
| 国家公开状态 | 名称、战略文化、意识形态侧重性、核力量、三个存在值、IPG、是否在场 | 同左 | 完整状态 |
| 国家私人状态 | 不可见 | 本国常规力量、画像、标签及释义 | 所有国家的完整私人状态 |
| 世界状态 | 回合、冲突、核使用历史、公开联盟 | 公共内容相同 | 完整世界状态 |
| 联盟状态 | 已公开的联盟及其公开/终止事件 | 本国秘密或公开联盟、邀请、合同、借调请求、回应、返还和失败原因 | 全部合同、请求、回应、账本和事件 |
| 推理状态 | 不可见 | 本国上一轮有效威胁评估、公开历史 | 所有决策、理由、模型调用和失败记录 |

对手的 `conventional`、`profile`、`tags`、威胁评估、联盟条款和借兵数额不会出现在国家 Agent 的视图中；`nuclear` 是公开实时状态。各国也看不到其他国家尚未提交或尚未公开的当轮行动。

## 2. 国家 Agent 状态

### 2.1 身份与固定设定

| 字段 | 初始设置 | 可见性 | 更新方式 |
| --- | --- | --- | --- |
| 国家 ID | 场景 `countries` 的键 | 公开 | 永不改变 |
| `name` | 必填文本 | 公开 | 永不改变 |
| `profile` | 可选文本，默认空字符串 | 仅本国 | 永不改变 |
| `strategic_culture` | 必填：国际主义、民族主义、进步主义、现实主义 | 公开 | 永不改变，不直接提供数值加成 |
| `strategic_culture_knowledge` | 程序根据知识词典生成 | 本国完整状态 | 永不改变 |
| `ideology_focus` | 必填整数：1–10；1 淡漠，10 狂热 | 公开 | 永不改变，不直接提供数值加成 |
| `ideology_focus_knowledge` | 程序根据知识词典生成 | 本国完整状态 | 永不改变 |

战略文化会进入提示词，约束 Agent 的解释和决策倾向，但结算器不会因为某种文化自动增减数值。

意识形态侧重性也会进入提示词。数值越高，Agent 越应考虑原则一致性、意识形态差异和对外改造目标，越不容易接受跨意识形态妥协；数值越低，越偏向安全、利益和跨制度合作等现实考量。它不会自动修改行动门槛、IPG或战损。

### 2.2 存在状态与全球存在指数

三个权威存在状态均在场景中设置，初值范围为 0–100：

| 字段 | 含义 | 是否更新 |
| --- | --- | --- |
| `economic_presence` | 经济网络、市场、供应链和资源影响 | 会，因存在转移变化 |
| `military_presence` | 基地、部署、投送和持续军事影响 | 会，因存在转移变化 |
| `soft_presence` | 制度、外交、文化、规范与舆论影响 | 会，因存在转移变化 |
| `global_presence` | 全球存在指数 IPG | 派生值，每次结算后重算 |

默认公式为：

```text
IPG = 0.43 × economic_presence
    + 0.21 × military_presence
    + 0.36 × soft_presence
```

`global_presence` 不能由场景或 Agent 直接设置。三个权重可由规则配置覆盖，但必须均为正数且总和为 1。存在值在游戏中可超过 100；支付方的每个维度最低降到 0。

### 2.3 军事力量与核能力

| 字段 | 初始设置 | 可见性 | 更新方式 |
| --- | --- | --- | --- |
| `conventional` | 场景设置，0–100 | 仅本国 | 战损、借调和返还会改变 |
| `nuclear` | 场景设置，0–100 | 公开 | 核战损、借调和返还会改变，并实时决定核权限 |

初始 `conventional < 40` 时，`nuclear` 必须为 0。开局后不再用常规力量自动生成核力量。核权限完全根据当前 `nuclear` 动态计算：`0` 不能选择核行动；`1–40` 只能选择规则门槛低于 45.0 的核行动；`>=41` 可以选择全部核行动并具备自动二次打击。借调、归还或战损改变 `nuclear` 后，权限随之改变。实际核使用还要求本次核投入大于 0。

### 2.4 是否在场

| 字段 | 初始设置 | 可见性 | 更新方式 |
| --- | --- | --- | --- |
| `alive` | 场景必须为 `true`，省略时默认 `true` | 公开 | IPG 耗尽、互相战略核战争或投降结算时可变为 `false` |

退场国家不再生成决策，也不能成为行动、联盟或借调的有效参与者。

### 2.5 国家画像标签

`tags` 是可选的本国私人背景，目前只允许 `stakeholders`。它可以用 `allies`、`adversaries`、`others` 数组引用其他在场国家 ID，也可以用 `description` 补充描述未单独建模的集团。这里的盟友只是本国设定或认知，不会自动建立规则层面的真实联盟。

程序将 `stakeholders` 解析为带定义和来源的 `tag_knowledge`。二者在游戏中保持不变，仅进入本国提示词，不自动修改存在、军力、冲突、联盟、战损或胜负。其他旧画像标签不再作为运行状态接受；原始内容只保留在知识词典中用于资料追溯。

### 2.6 私人威胁评估

国家每轮可以提交 `threat_assessment`。非空内容在结算后保存为：

```json
{"round": 1, "text": "本国的威胁判断"}
```

系统仅保留该国最近一次非空评估，下一轮以 `last_threat_assessment` 提供给同一国家。它不公开，也不直接改变任何数值。

## 3. 世界状态

### 3.1 场景与规则状态

| 字段 | 来源 | 更新方式 |
| --- | --- | --- |
| `rules_version` | 必须为 `v6.0` | 固定 |
| `scenario_id`、`name` | 场景元数据 | 固定，不参与结算 |
| `world_context` | 场景文本 | 固定，提供给所有国家提示词 |
| `max_rounds` | 场景或命令行，1–30 | 开局确定后固定 |
| `rule_config` | 可选场景覆盖 | 开局合并并校验，运行中固定 |
| `round` | 运行时从 1 开始 | 未结束时结算后加 1；结束时停留在终局轮次 |

### 3.2 核行动范围

系统不保存国家区域或国家间距离，核行动不检查目标的地理位置。`nuclear = 0` 时不能选择核行动；`nuclear = 1–40` 时只能选择门槛值低于45.0的核行动；`nuclear >= 41` 时可以选择所有核行动。实际核使用还必须满足行动门槛、当前核力量大于0以及实际投入核力量大于0。

### 3.3 有向冲突值

`conflicts[A][B]` 表示 A 对 B 的累计冲突值，是公开、有方向的状态。A 对 B 与 B 对 A 独立计算：

```text
new_conflict[A][B] = max(0, old_conflict[A][B] + effective_action_delta)
```

行动原始增量来自 `rules.json`。默认范围从完全投降 `-9.5` 到战略核战争 `100`，保持不变为 `0`。正增量行动还要经过连续施压衰减，负增量和保持不变不衰减。冲突值没有上限，但不能低于 0。冲突双方两个方向都为 0 时不能选择负增量行动。

这里的“行动门槛”是本轮开始时行动方对特定目标的有向累计冲突值。A 对 B 选择核行动时，只检查 `conflicts[A][B]`；`conflicts[B][A]` 不能代替，本轮行动即将增加的数值也不能补足本轮自身门槛。

| 核行动 | 默认行动门槛 |
| --- | ---: |
| 核信号释放 | 12.5 |
| 核军事预备 | 17.5 |
| 核武器示威 | 25 |
| 核威胁 | 35 |
| 有限核武器使用 | 45 |
| 升级性核行动 | 57.5 |
| 扩大核打击行动 | 72.5 |
| 战略核威胁 | 85 |
| 最后核警告 | 95 |
| 战略核战争 | 100 |

门槛来自当前 `actions` 配置，场景覆盖规则参数时以实际配置为准。达到门槛只表示该行动可以被选择，不代表系统自动使用核武器。有限核武器使用、升级性核行动、扩大核打击行动和战略核战争属于实际核使用，还要求当前核力量及本次核投入均大于0；其他核行动只是信号、示威或威胁。

### 3.4 核威胁历史与核使用历史

| 字段 | 可见性 | 更新方式 |
| --- | --- | --- |
| `threat_history[A][B]` | 主持人内部 | 记录已计入冲突但不应在后续轮次反复产生优势的核威胁贡献 |
| `nuclear_used` | 公开 | 一国实际执行过核使用后永久加入列表 |
| `pressure_streaks[A][B]` | 公开 | 记录 A 对 B 连续使用的正增量行动类别与连续轮数；中断、降级或更换类别后重置 |

实际核使用包括：有限核武器使用、升级性核行动、扩大核打击行动、战略核战争。战略核威胁和最后核警告只是威胁，不会把国家加入 `nuclear_used`。

核威胁增量保留在累计冲突值中，但只在使用当轮计入有效优势。若任一相关国家已经实际使用过核武，本轮威胁按原行动增量计算；否则按默认 `threat_effect = 35` 计算。

### 3.5 联盟和借调状态

主持人维护以下状态：

| 字段 | 内容 | 可见性 |
| --- | --- | --- |
| `alliances` | 双方、是否有效、是否公开、成立/公开/终止轮次、提供与返还条款 | 只公开已触发公开条件的有效联盟双方；条款仅双方可见 |
| `alliance_invitations` | 邀请方、受邀方、条款、状态和轮次 | 仅邀请双方 |
| `alliance_loans` | 实际借调、应返、已返、是否关闭 | 仅联盟双方 |
| `pending_loan_requests` | 跨轮借调请求、力量类型、数量、创建轮、回应轮和状态 | 仅联盟双方 |
| `loan_responses` | 出借方对借调请求的接受或拒绝 | 仅联盟双方 |
| `alliance_public_events` | 联盟被公开，以及公开联盟终止 | 公开 |
| `alliance_private_events` | 邀请、借调、返还、失败和详细终止原因 | 仅相关方 |

联盟状态更新规则：

1. 第 r 轮发出的邀请，只能在第 r+1 轮接受或拒绝；到期仍未有效处理则过期。联盟成立后默认只对双方可见。
2. 出现以下任一情况时不能结盟：邀请双方已有非零冲突值；本轮一方准备对另一方采取正增量行动；双方已经是盟友；受邀方的现有公开盟友与邀请方已有冲突，或邀请方本轮准备对该公开盟友采取正增量行动。秘密盟友不触发最后一项限制。这里的“正增量行动”包括外交、经济和军事施压，不仅指战争。
3. 当一方从同一盟友借入且尚未归还的 `conventional` 或 `nuclear` 中，任一项累计达到 1 时，联盟立即强制公开。多次小额借调累计计算；公开后即使归还力量，联盟也不会恢复秘密。
4. 盟友之间发生或计划发生正增量行动时，联盟立即终止，然后才处理本轮借调。公开联盟的终止会公开，秘密联盟的终止只通知双方。
5. 借调把 `conventional`/`nuclear` 从出借方余额转入借入方余额；它不改变存在值，但核力量转移会立即改变双方的核行动、投送和二次打击权限。联盟公开只暴露双方关系，不公开合同、借调事实或数值。
6. 出借方已密封投入行动的力量会先被保留，不能再用于出借。超过合同上限的请求失败但不自动毁约；出借方接受后实际余额不足属于无力履约，会终止对应联盟。
7. 返还从借入方余额转回出借方并更新账本。选择关闭但仍有未偿承诺时，联盟因违约终止。
8. 未归还的剩余力量不会由系统自动收回。

### 3.5.1 跨轮借调机制

借调按照跨轮请求和密封回应处理：

1. 第 r 轮，B 根据有效的 A-B 盟约向 A 提出请求。主持人校验参与方存活、盟约有效、力量类型和数量合法以及合同上限，然后保存到 `pending_loan_requests`。
2. 请求只对 A、B 和主持人可见。第 r 轮不转移力量，B 不能立即使用请求中的力量。
3. 第 r+1 轮，A 在密封决策中通过 `loan_responses` 接受或拒绝。未回应按拒绝处理。
4. B 可以提交依赖该请求的条件行动，并在行动的 `requires_loan_request_ids` 中显式列出请求 ID。B 看不到 A 的同轮回应。
5. A 接受后仍须通过盟约有效性、合同上限和实际余额检查。只有实际转移完成后，B 的依赖行动才可能生效。

核心校验链为：

```text
盟约有效性 -> 出借方履约意愿 -> 出借方实际能力 -> 力量转移 -> 依赖行动校验
```

### 3.5.2 盟约破裂与请求失败

以下情况会使相关盟约立即破裂：

- 一方主动解除盟约；
- 盟友之间出现正增量行动；
- 新公开联盟使原盟约与第三方冲突关系不兼容；
- 出借方拒绝请求或到期未回应；
- 出借方接受后因实际力量不足而无法履约。

以下情况默认只使请求失败，不自动破坏盟约：

- 请求数量超过盟约承诺上限；
- 请求格式、力量类型或请求主体不符合盟约；
- 回应引用不存在、过期或无权处理的请求。

如果盟约已经因任何原因失效，该盟约下所有尚未完成的借调请求必然失败，依赖这些请求的行动取消。

新公开联盟还会触发第三方兼容性检查。例如 A-C 联盟公开后，如果 B-C 已有非零冲突，或者 B 与 C 本轮任一方准备对另一方采取正增量行动，则 A-B 盟约失效。只有公开联盟触发该限制，秘密联盟不能被第三方据此推断或约束。

### 3.5.3 联盟事件与可见性

联盟状态变更和内部事件必须在对应结算步骤立即生效，供同轮后续规则读取；“回合末生成事件”只表示回合末统一投影和发布，不表示延迟改变状态。

- **状态事件**：立即更新盟约、请求、账本和力量状态。
- **公开事件**：回合末写入公开记录。公开联盟终止必须公开。
- **私有通知**：秘密联盟的建立、拒绝、无力履约和破裂只通知相关双方。
- **完整审计**：保存请求、回应、处理顺序、计算过程、失败原因和结果。

事件发布不得提前泄露密封决策，尤其不能在所有国家完成本轮提交前向 B 透露 A 的接受或拒绝选择。

## 4. 每轮 Agent 决策状态

每个在场国家必须基于自己的轮初快照提交且只提交以下字段：

| 字段 | 性质 | 是否延续到下一轮 |
| --- | --- | --- |
| `round`、`country_id`、`snapshot_hash` | 快照绑定与防串轮校验 | 否 |
| `assessment` | 私有现状评估 | 仅审计记录 |
| `forecast` | 私有对手预测 | 仅审计记录 |
| `declaration` | 对外声明，可真实也可欺骗 | 当轮公开记录 |
| `rationale` | 私有决策理由 | 仅审计记录 |
| `threat_assessment` | 私人威胁判断 | 最近一次非空值延续给本国 |
| `actions` | 对不同目标的密封行动和军力投入 | 经结算更新世界状态 |
| `alliance_invites` | 联盟邀请及条件 | 更新邀请状态 |
| `alliance_responses` | 接受、拒绝或反向提供 | 更新邀请/联盟状态 |
| `alliance_breaks` | 单方解除联盟 | 更新联盟状态 |
| `borrows` | 创建下一轮到期的借调请求 | 更新 `pending_loan_requests`，当轮不转移力量 |
| `loan_responses` | 接受或拒绝到期借调请求 | 更新请求、盟约并执行后续履约检查 |
| `returns` | 返还力量及是否结清 | 更新军力、账本和可能的联盟状态 |

一国对同一目标每轮最多一项行动，但可以同时对多个国家采取行动。所有国家先独立提交密封包，主持人收齐后才统一处理；声明不约束实际行动。

每项行动可以通过 `requires_loan_request_ids` 声明借调依赖。任一依赖请求未成功转移时，只取消对应行动，不取消该国其他无关行动。已经完成转移的力量不会因为依赖行动后来校验失败而自动归还。

模型返回不合法时会重试。超过重试次数后使用无行动的系统 fallback。借调依赖或实际力量校验失败的行动会单独写入 `settlement_fallbacks`。

## 5. 回合状态更新顺序

当前实现的确定性顺序如下：

1. 为每个在场国家构造独立轮初快照和哈希。
2. 依次调用模型，但每个模型只看到相同轮初状态，不看到其他国家当轮输出。
3. 校验全部决策包、行动门槛、投送范围和声明的军力上限。
4. 在副本上处理联盟冲突、邀请响应、解除、借调、返还和新邀请。
5. 若实际借调不足以支持行动，将相关国家行动替换为空，并从第 4 步重新计算，直到不存在新的执行失败。
6. 根据遭受的升级性核行动、扩大核打击行动或战略核战争生成自动二次打击；有限核武器使用不触发。
7. 根据上一轮 `pressure_streaks` 计算每项正增量行动的重复衰减倍率，更新 `pressure_streaks`。
8. 使用有效行动增量更新 `nuclear_used`、有向 `conflicts` 和 `threat_history`。
9. 仅按双方本轮有效行动增量计算 IPG 优势、存在转移请求和战损。
10. 扣除外交与经济施压成本，写入 `pressure_costs`。
11. 按支付方、存在维度、受益国稳定排序结算存在转移，更新 `alive`。
12. 扣除常规和核战损，处理相互战略核战争与投降。
13. 重算所有国家 IPG，判断终局；未结束则 `round + 1`。
14. 保存本轮非空私人威胁评估、公开记录和完整审计记录。

### 5.1 跨轮借调结算顺序

第 4、5 步中的跨轮借调采用以下稳定顺序：

1. 冻结所有密封决策，检查行动方、出借方和借入方是否存活。
2. 使回合开始时已经终止、过期或失效的盟约请求失败，并取消对应依赖行动。
3. 处理本轮主动毁约。盟约立即失效，不再执行相关接受回应。
4. 处理盟友之间的正增量行动。相关盟约立即失效。
5. 处理新公开联盟造成的第三方不兼容，立即终止受影响盟约。
6. 读取出借方回应。拒绝或未回应使请求失败、盟约破裂、依赖行动取消。
7. 为出借方自己的有效密封行动预留常规力量和核力量。
8. 处理合法归还；实际归还的力量可以在同轮重新进入出借方可用余额。
9. 检查本次请求与未归还同类力量之和是否超过合同承诺上限。超过时只拒绝请求。
10. 计算出借方实际可用力量：

```text
可用力量 = 当前力量 - 自身行动预留 - 本轮此前已成功借出的力量
```

11. A 已接受但可用力量不足时，认定无力履约，请求失败且对应盟约立即破裂。
12. 同一出借方有多个已接受请求时，按借入国 ID、请求 ID 的稳定顺序处理。后续余额不足只影响相应联盟。
13. 完成力量转移并更新借调账本。未归还同类力量累计达到 1 时联盟立即且永久公开。
14. 逐项复核 B 的依赖行动，包括请求履约、总资源、行动门槛、实际核投入和重复使用。失败时只取消对应行动。
15. 进入自动二次打击、冲突、存在转移、战损和终局结算。
16. 回合末统一生成公开投影、双方私有通知和完整审计记录。

跨轮机制的详细字段和验收用例另见 `docs/联盟与跨轮借调状态机.md`。

## 6. 存在优势与转移

对国家 A、B，先得到双方本轮结算使用的有效行动增量 `EA`、`EB`。累计冲突值不再在后续回合重复产生存在收益：

```text
difference = abs(EA - EB)
```

如果一方实际使用核武而另一方采取常规军事行动：

```text
theta = 1 + min(difference / 100, 1)
```

其他组合 `theta = 1`。IPG 优势请求为：

```text
IPG_claim = difference × theta
```

有效值较高的一方是该双边结算的胜方。根据胜方行动类别，将 IPG 优势拆到三个存在维度：

| 胜方行动类别 | 经济份额 | 军事份额 | 软实力份额 |
| --- | ---: | ---: | ---: |
| 维持现状、撤退、投降等 | 43% | 21% | 36% |
| 外交行动 | 10% | 0% | 90% |
| 经济行动 | 80% | 0% | 20% |
| 常规军事行动 | 20% | 70% | 10% |
| 核相关行动 | 40% | 50% | 10% |

由于存在状态和 IPG 权重不同，某一维度的实际请求为：

```text
dimension_claim = IPG_claim × category_share / presence_weight
```

同一支付方同一维度同时欠多个国家时，若余额不足，按各请求比例分配并降至 0；不会出现负值。已经退场的受益方不能获得转移，相应份额退回支付方。

### 6.1 连续施压衰减与成本

同一国家连续对同一目标使用同一类别的正增量行动时，默认倍率为：

| 连续轮次 | 有效增量倍率 |
| --- | ---: |
| 第 1 轮 | 1.00 |
| 第 2 轮 | 0.75 |
| 第 3 轮 | 0.50 |
| 第 4 轮及以后 | 0.25 |

本轮未对该目标采取正增量行动，或更换外交、经济、常规军事、核行动类别时，连续次数重置。有效增量同时用于增加累计冲突和计算本轮存在优势。外交施压从行动方 `soft_presence` 扣除 `有效增量 × 0.1`；经济施压从行动方 `economic_presence` 扣除 `有效增量 × 0.15`。实际扣除最低为 0，并完整写入 `pressure_costs`。

### 6.2 声明与事实

每轮公开声明保存为 `unverified_declarations`，只表示某国曾公开声称相关内容，可能真实、虚假或尚未执行。它不会直接创建会议、协议、撤销措施、部署或其他世界事件。规则实际执行的行动、存在转移、施压成本、自动二次打击和终局结果保存为 `confirmed_facts`。下一轮 Agent 历史视图明确分开这两类信息，并被要求只把当前状态和 `confirmed_facts` 当作已确认事实。

## 7. 战损更新

只有出现常规军事行动或实际核使用的国家对才产生战损。军力投入不会自动消耗，只有计算出的损失会从国家余额扣除。

### 7.1 常规战损

```text
intensity = min((post_conflict_A + post_conflict_B) / 20, 1)
base_rate.conventional = 0.1
base_rate.nuclear = 0
```

### 7.2 核战损

```text
intensity = min((post_conflict_A + post_conflict_B) / 400, 1)
```

按双方本轮最高实际核行动门槛选择基础损失率：

| 最高门槛 | 常规力量率 | 核力量率 |
| ---: | ---: | ---: |
| 45 | 0.50 | 0.12 |
| 57.5 | 0.60 | 0.15 |
| 72.5 或更高 | 0.70 | 0.18 |

### 7.3 力量倍率和最终损失

对 A，使用双方本轮投入的常规力量：

```text
multiplier_A = clamp(
    sqrt((B_conventional投入 + 1) / (A_conventional投入 + 1)),
    0.3,
    2
)

loss_A[kind] = min(
    A投入[kind],
    A投入[kind] × intensity × base_rate[kind] × multiplier_A
)
```

所有数值按 6 位小数、`ROUND_HALF_UP` 处理。一个国家同时参加多场冲突时，各场损失累加，最后统一从 `conventional` 和 `nuclear` 扣除，最低为 0。

## 8. 自动二次打击

国家满足以下条件时，主持人自动生成二次打击：

- 当前核力量至少为 41；
- 本轮遭受至少一个国家的升级性核行动、扩大核打击行动或战略核战争。有限核武器使用不计入自动二次打击触发条件。

默认受保护报复力量：

```text
reserve = 当前核力量 × 0.25
每个攻击者的报复投入 = reserve / 触发二次打击的攻击者数量
```

报复行动镜像攻击者所用的触发行动等级。如果该国已主动对该攻击者选择任一实际核行动（包括有限核武器使用），不重复生成；否则自动报复会替换该方向原有的非核行动。自动报复进入正常冲突、存在转移和战损结算，并写入 `automatic_second_strikes`。

## 9. 终局状态

每轮结算后生成：

```json
{
  "finished": true,
  "winner_id": "C1",
  "reason": "ipg_victory"
}
```

`outcome.reason` 可能为：

| 原因 | 条件 |
| --- | --- |
| `mutual_surrender` | 开始结算时仅剩两个在场国家，且双方在同轮互相完全投降，无胜者 |
| `all_eliminated` | 无在场国家，无胜者 |
| `last_country` | 仅剩一个在场国家，该国获胜 |
| `ipg_victory` | 某在场国 IPG 至少 50，且领先其他最强国家至少 30 |
| `round_limit` | 达到最大轮数仍无其他终局，无胜者 |

双方互相选择“战略核战争”会使双方退场。如果所有其他在场国家都在同一轮对同一个目标选择“完全投降”，目标国成为唯一在场国家并以 `last_country` 获胜；只要仍有一个其他在场国家没有向该目标投降，就不触发该胜利，已经投降的国家也不退场，视为暂时苟和。只有开始结算时恰好剩余两个在场国家且双方互相选择“完全投降”，才以 `mutual_surrender` 无胜者结束；三个或更多在场国家中的任意一对互相投降，不会单独结束游戏。

## 10. 运行与审计状态

完整 `run.json` 还保存以下实验状态，它们用于审计和复现，不直接参与国家决策公式：

- `initial_state`、每轮 `state`、`final_state`。
- 原始 `decisions`、实际 `effective_decisions`、完整 `settlement`。
- 模型调用 `records`，包括重试、错误、响应和可选提示词。
- `fallback_count`、`run_status`、`model_settings`。
- 完整 `rule_config`、配置指纹和源代码指纹。
- 每轮公开投影 `public` 及最终 `result`。

回放不调用模型，而是从 `initial_state` 和保存的密封决策重新执行每轮结算，并逐项比较状态、结算记录和公开记录。因此同一规则代码和配置下，状态更新应当完全可复现。
